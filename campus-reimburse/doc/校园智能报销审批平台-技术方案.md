# 校园智能报销审批平台 — 技术方案

面向师生的报销审批 OA：**线上提交、自动流转、全程可查。**

修订日期：2026-09-15。当前仓库为方案阶段，以下为实施设计，不代表已经开发或通过压测。

## 0. 选型结论与实施边界

**采用模块化单体 + MySQL 事务 + Redis 共享会话 + 校内对象存储 + 数据库持久化后台任务。** 优先保证财务数据正确、安全可追溯和故障可恢复，通过应用多实例、任务隔离、索引和分页支持增长。

适用前提：单校部署、PC Web 为主、差旅两级审批、常规 Java 开发团队。尚未提供用户数、年单据量、峰值请求和服务器资源，因此本方案是此约束下的推荐基线，不承诺未经测试的并发上限。

| 阶段 | 范围 |
| --- | --- |
| 一期 | PC Web；两张差旅单（申请不算钱、回来报销）；手工填票；主管/学院/财务审批；进度可见；PDF 与财务 XLSX/CSV/JSON；引导、权限、审计、防重、任务、备份。OCR/验真只留端口，不调用 |
| 二期 | OCR `VatInvoiceOCR`、验真 `VatInvoiceVerifyNew`、调试台；采购/科研、CAS、看板；复杂流程再评估 Flowable |
| 三期 | 电子签章、财务对接、Ollama（FAQ） |

产品范围、双端页面、审批链与进度交互见[实现方案](./校园智能报销审批平台-实现方案.md)。库表以本文第 5 节为唯一字段定义。

**OCR / 验真二期必做，一期不调用。** 代码预留 `OcrPort.recognize`（`VatInvoiceOCR` + ImageBase64）与 `InvoiceVerifyPort.verify`（`VatInvoiceVerifyNew`）。识别成功不等于真票。配置默认 `ocr.enabled=false`、`invoice-verify.enabled=false`。

```text
校园网 HTTPS → Nginx → Vue 静态页面 / Spring Boot API（可多实例）
                                       ├─ MySQL：业务、票据占用、审计、任务
                                       ├─ Redis：共享会话、缓存、限流
                                       └─ 校内 MinIO/S3：附件、导出文件
```

模块：`auth`、`claim`、`workflow`、`file`、`ocr`、`notify`、`finance`、`audit`、`job`、`dataexchange`、`onboarding`、`common`。`claim` 只依赖端口，不直接调用腾讯或存储 SDK。API 实例不依赖本地会话和永久本地附件；worker 可独立扩容。

构建锁定依赖版本和容器镜像摘要；上线前做依赖漏洞扫描、许可证清单和组件支持周期复核。Java 21 不意味着自动解决数据库并发；一期采用常规有界线程池，不依赖虚拟线程获得容量保证。

一期不引入微服务、K8s、ES、分库分表、通用流程设计器。差旅主路径与页面以实现方案为准。

## 3. 安全与财务控制（一期必做）

以下是工程实施基线。学校的定级、测评和上线要求由信息化部门确认，技术组件清单不等于已通过等保测评。

### 3.1 身份、会话和数据权限

- 同源部署，Spring Security + Spring Session Redis；会话 Cookie 设置 HttpOnly、Secure、SameSite=Lax，登录后更换会话标识，退出销毁会话。会话过期、并发登录和管理员强制退出可配置。
- 本地密码使用 Spring PasswordEncoder 的 BCrypt，禁止明文和可逆加密密码；按账号与来源组合限速、临时锁定，避免永久锁定被滥用。敏感管理操作增加二次认证，二期接 CAS 后统一账号生命周期。
- Cookie 认证启用 CSRF，Vue/Axios 显式携带 Token，登录和退出后刷新 Token；禁止为了联调全局关闭 CSRF。CORS 使用明确白名单。
- 后端逐接口落实角色及数据范围：申请人仅本人；审批人仅授权待办及审批历史；财务仅授权部门；系统管理员不默认具有财务审批和全量票据读取权限。
- 列表、详情、附件、搜索、导出、统计使用同一数据权限规则；数据范围在 SQL 查询中生效，不能先全量读取再前端过滤。部门树授权明确是否包含子部门。
- 审批时重新读取处理人、当前节点和状态。申请人不得自批；指定人员失效或与申请人相同则停止流转并通知管理员配置合法处理人，不自动跳过节点。
- 权限变更后失效相关权限缓存或校验权限版本；后台任务执行及导出下载重新检查授权。授权不足的财务操作默认拒绝。

### 3.2 票据防重与人工确认

附件与确认发票、识别结果、占用分表，见第 5.4 节。`claim_file` 只存文件；`invoice_ocr_result` 存识别；`claim_invoice` 存人工确认；`invoice_occupation` 按 `invoice_key` 占用。

1. 附件上传不永久占用发票。SHA-256 仅用于相同文件提示，不能识别换图、扫描件形式的同票重复。
2. 按票据类型校验并规范化票号，保留前导零，生成非空 `invoice_key`。有代码票据使用“类型+代码+号码”；合法无代码票据使用“类型+号码”，不得把缺失的必填代码当合法无代码类型。
3. 提交事务中为已经人工确认的票据插入占用记录，由 `invoice_key` 主键拦截并发重复；不采用“先查没有、再无约束插入”。
4. 识别失败或关闭时仍可提交。`claim_form.invoice_check_status=PENDING` 直到财务确认全部 `claim_invoice`。财务通过前必须人工确认并写入占用；不要求 OCR 成功。
5. `RETURNED` 保留原占用，允许原单修改后重提；替换票据时在事务内核验新票并释放旧票，记录修改轨迹。`REJECTED/CANCELLED` 释放未通过单据的占用并记审计。
6. `APPROVED` 的票据持续占用，禁止普通删除或撤销释放；未来冲销、作废、财务对接另设授权流程。流程“审批通过”不等于“已经付款”。
7. 防重占用库覆盖历史年度，单据归档时不能清除有效占用。跨系统重复报销仍需财务对接，一期不能宣称全校所有系统防重。

### 3.3 附件与敏感数据

- 文件白名单 jpg/png/pdf，单文件 ≤10MB；另限制单据附件数、用户配额、上传频率、PDF 页数和解析耗时，初始附件数上限 20，可配置。
- 校验后缀、Tika MIME、实际解码结果；随机 object_key，禁止使用用户文件名拼接磁盘路径。上传对象须由后端确认归属、大小和校验和后才能绑定单据。
- 桶私有，下载和预览逐次校验单据权限；一期走鉴权流式转发，支持限速。原始文件默认附件下载；PDF/图片预览在隔离来源和受限环境中处理，设置正确 Content-Type、nosniff 和 CSP。
- 文件解析/扫描使用资源受限进程；有校方杀毒服务则接入。扫描或解析失败的附件不得直接提供主动内容预览；不能把 MIME 检查当杀毒。
- 手机号、银行卡等确需存储的敏感字段采用 AES-GCM，随机唯一 nonce、保存密钥版本；密钥与数据库分离，通过校方密钥服务或受限挂载秘密文件注入，支持轮换和恢复。列表脱敏，日志不记录明文。
- SQL 参数绑定，排序字段和动态列名用白名单；避免 `${}` 接收用户输入。用户备注默认按文本输出，富文本必须净化，禁止未经处理的 v-html。
- 云 OCR 的 Base64 仍传输票据内容；启用真实调用前落实校方数据出校流程。保持原服务端调用方式、开关和识别功能。

### 3.4 审计

一期落地 `sys_audit_log`，覆盖登录、提交、审批、撤销、票据确认、权限变更、附件访问、导入预检与执行、导出创建及下载、打印页访问；记录操作者、目标、结果、时间、请求追踪 ID，内容脱敏。**OCR 出网审计在二期随真接一并启用。**

业务状态修改与成功审计在同一事务提交；拒绝、异常等失败审计在原事务回滚后独立保存。关键财务写操作不能在审计持久化失败时静默成功。外部请求的意图与执行结果分别记录，不伪造原子性。

应用账号对审计和流转表仅有必要的 INSERT/SELECT 权限，无 UPDATE/DELETE/DDL；迁移账号独立。日志同步到受限的独立存储并监控投递失败。只插表不是绝对防篡改，数据库管理员仍需权限分离和操作审计。

## 4. 并发一致性与后台任务

### 4.1 审批及提交事务

单据增加 `version` 和 `workflow_round`。每次退回重提递增轮次，待办绑定轮次，旧请求不能操作新待办。

审批事务顺序：读取并校验权限 → 按预期状态、节点、处理人、版本条件更新单据 → 必要的票据占用校验 → 关闭当前待办 → 创建下一待办 → 写流转日志、审计、通知任务 → 提交。任一步失败全部回滚。

```sql
UPDATE claim_form
SET status = :next_status,
    current_node = :next_node,
    version = version + 1,
    updated_at = CURRENT_TIMESTAMP(3)
WHERE id = :id
  AND status = :expected_status
  AND current_node = :expected_node
  AND workflow_round = :expected_round
  AND version = :expected_version
  AND deleted = 0;
```

处理人只存在 `claim_todo`（当前 `OPEN` 行）。更新单据行数必须为 1，同时关闭对应待办并插入下一待办，同一事务。

更新行数必须为 1；为 0 返回状态冲突并要求刷新。目标状态由后端状态机计算，客户端不能指定任意下一状态。待办关闭同样要求 `OPEN` 和预期处理人/轮次，失败回滚整个事务。状态、日志和待办不能拆成多个独立事务。

提交、审批、撤销使用幂等键，唯一范围为“操作者+动作+请求键”，保存请求摘要、业务 ID 和结果。同键同内容重试返回原结果，同键不同内容拒绝；幂等结果与业务变更同事务提交。记录到期后，状态条件和数据库唯一约束仍保证业务正确。

多票据按 invoice_key 排序后占用，缩短锁持有时间；死锁只对整个幂等事务做少量有界重试。Redis 锁不作为财务一致性保障，事务内不调用 OCR、存储或邮件服务。

### 4.2 持久化后台任务

选择 MySQL `job_task`，不以单独 `@Async`、内存队列或 Redis 列表承担可靠任务。

- 业务和任务记录同事务写入；worker 使用带索引的短事务 `SELECT ... FOR UPDATE SKIP LOCKED` 批量领取，更新 RUNNING、lease_owner、lease_until、lease_token 后提交，再执行外部操作。
- 执行期间续租；回写结果必须匹配租约 token，过期 worker 不得覆盖新 worker 的结果。宕机或租约超时后可回收，采用至少一次执行与业务幂等，不承诺外部调用恰好一次。
- 失败指数退避加抖动，初始最多 3 次，超过后 FAILED 并告警；人工重试可审计。定时提醒使用时间窗口业务键去重。
- OCR、导出和通知使用独立并发额度，初始每 worker 分别 2/1/2；OCR 按服务商额度做全局限速，配置值经压测调整。队列积压应告警，不能通过无限增加线程解决。**OCR 额度仅二期启用。**
- OCR 结果只写入 `invoice_ocr_result`；仅草稿且用户未改确认字段时回填 `claim_invoice` 未确认列。不覆盖已确认值。
- 导出记录授权范围、筛选条件和截止时间；分批读取、按第 10 节所选格式流式写文件，完成后存入私有存储。重新校验下载权限，设置到期时间并清理临时文件；用户输入按文本单元格输出，防止公式注入。
- 一期限制每用户同时 1 个导出任务、单任务最多 10 万数据行；格式自身限制更低时按第 10 节执行；更大范围按时间拆分。普通导出是截止时间内的业务查询结果，不宣称严格财务快照；正式结账报表后续采用冻结快照。

## 5. 数据模型（3NF）

约定：MySQL 8.4 / InnoDB / utf8mb4；金额 `DECIMAL(12,2)`；时间 `DATETIME(3)` UTC；主键 `BIGINT AUTO_INCREMENT`。外键均指向有效行。业务查询禁止依赖 JSON 拆字段。

**3NF 规则（尽量遵守）：**

1. 一列一事；人员、行程、费用、角色用子表，不用逗号拼接。  
2. 姓名、部门名、项目名、交通中文名不写入单据，用 FK；展示时 JOIN。  
3. 申请时部门是单据事实，存 `claim_form.dept_id`（提交快照），不跟用户以后调部门而变。  
4. 派生值不落库：行程天数、OCR 总旗标、当前处理人（见待办）、退回原因（见流转日志最新 RETURN）。  
5. 报销不复制申请的行程/人员，用 `source_apply_id` 读取。  
6. 文件、识别结果、确认发票、占用四张表，不把票号写在附件行上。  
7. 例外（不参与业务查询）：`job_task.payload_json`、`invoice_ocr_result.raw_payload`、`claim_revision.snapshot_json`（仅审计对照）。

一期不用 `form_schema`、不用原 `claim_travel` / `claim_field`。

## 6. 数据量与性能设计

- 列表默认最近 90 天，每页 20、上限 100；允许授权用户选择历史时间窗口。深分页使用 `(created_at, id)` 游标，避免巨大 OFFSET；是否显示精确总数按页面需求决定，不能每页全量 COUNT。
- 查询显式列出所需字段，列表不读取 OCR JSON 和附件正文；权限过滤尽早进入 SQL，避免逐单查询导致 N+1。
- 先按慢查询和执行计划调整索引；索引过多也增加写入成本。连接池总量按“API 实例数×每实例池大小 + worker 连接”核算，保留运维连接；初始 API 每实例 20、worker 10，仅为压测起点。
- Redis 只缓存可重建数据；缓存未命中回源设并发上限，必要时返回繁忙，避免故障时击穿数据库。会话服务不可用时拒绝需认证操作，不降级绕过登录。
- OCR、数据导入、导出、附件下载分别限流；上传/下载带宽与普通审批延迟分开测量。对象以流方式读写，禁止全量文件常驻内存。
- 归档优先处理旧任务和通知；业务、审计、原始凭证的保留期由学校确定，归档仍须可授权检索。有效发票占用不能随归档移除。
- 一期不分库分表。读查询在优化后仍持续饱和才增加读副本，审批、占用和提交后的即时查询始终读主库；跨年报表瓶颈再采用汇总表或独立分析库。

## 7. 部署、运维和容量验收

### 7.1 推荐部署

开发环境用 Compose 一键启动，测试数据不得使用真实敏感票据。正式环境复用校方虚拟机及数据库服务：Nginx 入口、两份 API 实例分布在不同宿主机、独立 worker 资源配额、独立 MySQL/Redis/对象存储。资源不足时可先部署一份 API 试点，但明确存在维护中断，不能标记为高可用。

仅 HTTPS 443 面向校园网；数据库、Redis、对象存储仅对指定服务网络开放，管理入口通过运维网络/VPN。Swagger 生产关闭；Actuator 仅暴露必要健康和指标端点并做鉴权，不对用户网络开放配置与环境信息。

应用账号按库表最小授权；密钥禁止写入 Git、镜像和日志。发布前备份、演练数据库迁移，采用先兼容新增再切换的迁移方式；回滚应用不等于可以无损回滚破坏性数据库变更。

### 7.2 文件存储落地约束

为保持原 OCR 路径，代码继续通过 MinIO/S3 适配器从私有对象读取再发送 ImageBase64。学校已有受维护 MinIO 服务时直接复用；新采购/新部署则优先选择校内有明确安全维护和备份责任的 S3 兼容服务，做 SDK 读写、权限、流式下载和 OCR 读取兼容验证。

MinIO 社区服务端仓库已归档，**不能把固定旧社区镜像作为新生产环境的长期默认方案**。校方若尚无对象存储，开发可用隔离 MinIO 验证；真实票据上线前必须落实受维护的存储服务。不能为了交付自动把票据迁往公网，也不在一期自行建设复杂存储集群。第 2 节的 MinIO 表述代表保留的读取适配路径。

### 7.3 备份与恢复

上线前落实 MySQL 每日全备与持续 Binlog 备份，对象存储独立备份及版本保护；备份位于不同故障域并加密，密钥另行备份。主从复制、同机另盘都不能替代备份。

初始恢复目标：业务数据库 RPO ≤15 分钟、RTO ≤4 小时；附件备份延迟目标 ≤15 分钟，只有设施和演练满足后才能对外承诺。恢复时核对数据库附件引用、对象版本、票据占用和任务状态；恢复后已失去有效租约的任务允许幂等重跑。

上线前完整恢复一次，其后每季度演练；记录实际丢失窗口、恢复时间及附件抽查结果。若要求自动故障切换，入口、数据库、Redis 和对象存储必须各自具备校方运维支持的冗余方案；单纯增加 API 实例不满足此要求。

### 7.4 压测和验收

以下是待验证目标，不是现有能力。压测前记录 CPU、内存、磁盘类型、网络、组件版本和全部限流配置，并收集真实峰值修订目标。

| 场景 | 初始测试设计 | 验收关注 |
| --- | --- | --- |
| 数据规模 | 100 万单据、1000 万流转/审计记录，包含跨年与热点部门；附件容量单独按数量×平均大小测算 | 历史查询、权限过滤、索引和存储增长 |

监控至少包括接口 P95/错误率、数据库慢查询/锁等待/连接占用、任务最老等待时间与重试量、OCR 失败率、存储容量、备份失败。达到目标后再放量；瓶颈定位后优先优化 SQL、调整资源和 worker 并发，其次扩 API 实例。

## 8. 交付顺序

1. **基础骨架**：锁定依赖、数据库迁移、登录与部门权限、私有附件；写入 `OcrPort` 与腾讯云配置槽，**不跑识别**；验证引导编排和个人进度持久化。
2. **财务闭环**：差旅字段与费用明细、草稿自动保存、版本快照及退回对比、材料清单、主管/财务工作台及对应首次引导、**手工**票据确认及占用、事务/幂等、审计。
3. **可靠后台**：job_task 与 worker、通知、多格式导入导出、模板预检、任务中心及对应首次引导、限流及监控。
4. **上线验收**：快捷键与打印、多格式及异常导入导出、逐功能全流程引导及中断恢复、安全测试、并发正确性、混合压力、备份恢复和生产存储支持确认，记录结果再上线。

**二期 OCR：** 打开 `ocr.enabled`，实现角落识别按钮、OCR worker、Mock 与 `TencentVatInvoiceOcrAdapter.VatInvoiceOCR`（ImageBase64），以及识别引导。CAS、复杂工作流和看板仍不阻挡一期。

一期交付完成标准是“功能闭环 + 日常操作可用 + 权限隔离 + 财务并发正确 + 可恢复”，CAS、复杂工作流和看板不阻挡一期，但审计、防重、备份不能后移。

## 10. 日常操作功能补齐与实施规范

本节对照本项目技术方案与《天翼财务系统介绍与对接调研》，补充实际使用中高频功能。**这里的“缺失”指文档尚未定义，并非已经验证代码中不存在。** 天翼公开资料可供参考的方向包括项目授权、附件、审批和财务关联；热键、多格式导入导出等未取得天翼现网功能证据，以下明确作为我方产品建议，不宣称复制天翼已有功能。

| 费用明细与金额校验 | 只有总额、差旅固定字段 | 交通、住宿等逐行录入及总分核对，方便财务核减和导入 | P0 / 中 |
| 审批工作台 | 只有待办和流转表 | 单据与附件并排、常用意见、下一笔、逾期提示 | P0 / 中 |
| 退回原因与修改对比 | 有 RETURNED，无展示规范 | 明确退回原因、定位字段、比较重提版本 | P0 / 中 |
| 批量审批 | 未定义 | 高频同类待办处理，逐单事务和结果列表 | P1 / 中；一期不开放批量财务最终通过 |
| 任务中心 | 后台有任务，无用户入口 | 查看导入导出进度、错误、下载和取消 | P0 / 中 |
| 经费项目选择与分摊 | 仅在对接调研中讨论 | 学校项目编码、使用授权、余额及多项目分摊 | P2 / 高；现在预留字段映射边界 |
| 财务受理、核算与付款分开显示 | 主方案仅内部审批状态 | 对接后查看核减、凭证、部分支付、退汇 | P2 / 高；未对接时显示未获取 |
| 借款冲抵、代办、审批代理 | 未落地 | 差旅借款、秘书代填、审批人请假 | P2 / 高；必须定义授权、有效期和财务规则后实施 |

一期先形成“方便填、方便审、方便查、数据可进可出”的闭环。多项目、借款、代理审批等按实际制度安排，不为完善功能列表扩大一期业务范围。

### 10.2 热键和操作效率

使用统一前端命令注册层（如 `usePageCommands`），按钮和快捷键调用同一动作，权限、校验和幂等规则一致。基础键盘支持不能依赖开启快捷键模式。

| 按键 | 作用 | 生效范围及限制 |
| --- | --- | --- |
| Tab / Shift+Tab | 在输入项和按钮间移动 | 全站合理焦点顺序，焦点清晰可见 |
| Enter | 执行查询或激活已聚焦按钮 | 搜索区提交查询；多行备注换行；不得自动提交整张报销单 |
| Esc | 关闭最上层菜单、预览或弹窗 | 有未保存改动先提示；不放弃正在提交的事务 |
| Ctrl+S / macOS Cmd+S | 保存当前草稿 | 仅可编辑表单页且动作可用时拦截；不触发报销提交 |
| 左 / 右方向键 | 查看上一张／下一张附件 | 仅附件导航区获得焦点且不在输入控件时生效 |
| Ctrl+Enter / macOS Cmd+Enter | 打开提交或当前审批动作的确认框 | 可选快捷模式；必须再次确认，不直接审批通过 |

快捷键说明入口放在页面帮助区和对应按钮提示中，业务快捷键可以关闭。Ctrl+F、Ctrl+P 等浏览器常用键不全局覆盖；打印用页面按钮打开专用打印视图。对于系统或浏览器无法可靠拦截的组合键，使用按钮兜底，不承诺跨平台通用。

处理输入法组合输入 `isComposing`，中文选词期间不得提交；忽略长按重复事件；弹窗内限制焦点，关闭后归还触发按钮。除显式保存和可选确认框命令外，输入框、contenteditable 中不触发页面命令。对提交、驳回、撤销、删除不提供默认单字符快捷键。验收覆盖实际使用的 Windows 浏览器、macOS 浏览器及中文输入法。

### 10.3 表格查询、列设置和统计

- 通用列表支持服务端组合筛选：单号精确查询、标题、申请人、授权部门、状态、申请日期、金额范围。项目条件在项目模块上线后启用；筛选项随角色变化。
- 单号精确查询可显式跨时间查找；普通列表仍默认最近 90 天，避免误以为旧单不存在。姓名查询需先限定授权范围。
- 表格支持列显隐、调整宽度、固定标识列及服务端排序，白名单列才可排序。返回列表时恢复筛选、位置和展开项；查询条件变化后清空选择。
- 底部明确显示“本页合计”和“全部筛选结果合计”。跨页汇总由服务端在同一权限和筛选口径下计算，按需加载；不把前端当前页求和当总额。不具备金额权限时也不可见合计。
- 列设置只改变显示，不能增加字段权限。显示用列集合与导出列集合分别选择，敏感字段需独立授权；P1 保存命名筛选方案和默认列设置。
- 不建设浏览器内无限行 Excel：保留服务端分页，每页上限 100，大批量数据通过导入导出处理。

### 10.4 多格式导入导出范围

统一使用 `DataImportPort` / `DataExportPort` 或同等服务边界，转换为同一业务 DTO 后执行现有业务校验，不为每种格式另写一套权限与入库逻辑。

| 格式 | 导入 | 导出 | 用途与实现 |
| --- | --- | --- | --- |
| XLSX | P0 | P0 | 默认模板与办公交换；POI XSSF 事件读取、SXSSF 流式写出 |
| XLS | P0 | P1 | 兼容旧表；POI HSSF 事件读取，小规模写出；导出含表头最多 65,536 行，超限要求 XLSX/CSV，禁止截断 |
| CSV | P0 | P0 | 大清单和系统交换；Apache Commons CSV 流式读写 |
| TSV | P0 | P0 | 制表符分隔的表格交换；Commons CSV 明确配置分隔与引号规则 |
| PDF | 不作为表格导入 | P0 打印页另存；P2 服务端生成 | 报销单和审批轨迹留档，不能当机器数据交换格式 |
| JSON / XML | P2 按正式接口契约 | P2 按正式接口契约 | 专用财务对接，不开放任意 JSON/XML 数据库导入 |
| ODS、XLSM、加密工作簿 | 一期不支持 | 一期不支持 | 提示转换为标准 XLSX/CSV；不执行宏或自动解密 |

这张表的 PDF“不可表格导入”仅限制结构化数据导入，**原 jpg/png/pdf 发票附件上传和 OCR 路径不受影响**。XLS/XLSX 文件内容与扩展名须匹配，不接受 HTML 表格改后缀伪装 Excel。

CSV/TSV 导出默认 UTF-8；面向 Excel 的 CSV 提供带 BOM 的选项；导入支持 UTF-8（含 BOM）和用户明确选择的 GB18030，先预览再确认，不悄悄替换乱码。带逗号、制表符、引号、换行的字段按所选格式转义，不能简单 split 分割。

### 10.5 导出交互和数据口径

导出入口提供：格式、当前页／已选记录／全部筛选结果、列集合、排序和脱敏说明。一期已选记录只覆盖当前页明确勾选的 ID；跨页数据通过“全部筛选结果”导出，不把表头全选暗示为选中全库。

服务端重新构造授权查询，不信任前端提供的列名、用户 ID 或计数。创建、执行和下载阶段均校验；若执行期间权限发生变化，取消结果并要求重新生成，不能只检查文件所有者。下载到用户设备后的副本无法远程收回，页面说明用途和保管责任。

统一后台生成，任务中心显示待执行、生成中、完成、失败、取消和过期；有阶段和已处理行数，只有总量可靠时才显示百分比。导出文件默认 7 天过期，下载记录审计；失败展示可理解原因和重试入口。

XLSX、CSV、TSV 单任务最多 10 万数据行，XLS 受其更低行数限制；每用户同时 1 个导出任务。超限提示拆分日期，不默默少导。XLSX 可在独立说明工作表记录筛选和口径；CSV/TSV 保持单一表头数据结构，说明放任务详情，不插入破坏机器解析的说明行。

金额按数值和明确小数位输出，单号、票号、工号、银行卡等按文本处理。XLSX/XLS 对用户内容写文本单元格；CSV/TSV 的引号不能阻止公式执行，对自由文本中可能被表格软件解释为公式的前缀进行安全转义。金额等已验证类型不按自由文本处理。

CSV/TSV 无单元格类型，无法保证 Excel 双击后保留长编号和前导零；涉及此类编号推荐 XLSX，CSV/TSV 使用文本列导入向导。办公安全转义可能改变字符串表示，因此它不作为天翼机器交换协议；机器交换使用经确认、版本化的专用模板及解析规则。

普通清单展示生成时间和查询口径；执行期间业务变化可能造成结果与原页面不同，不宣称财务冻结快照。正式财务归档文件在 P2 实施受控快照和服务端 PDF，不以浏览器打印件代替电子签章凭证。

### 10.6 导入对象、预检和确认流程

一期导入对象限定为：本人差旅草稿及费用明细；管理员授权范围内的部门、人员基础档案和字典。人员档案导入不得包含密码、角色授予或项目授权，已接入统一身份的数据源不允许被文件覆盖。票据信息可以作为待确认数据随草稿导入，但不自动占用票号，不自动标记 OCR 成功。

不允许普通数据导入直接修改审批状态、通过记录、凭证、支付结果、有效票据占用或审计历史。差旅导入成功仅生成草稿，仍需本人补附件、确认票据信息并正常提交；不把导入功能扩展为代办授权。

流程：**选择业务类型 → 下载对应版本模板 → 上传 → 选择工作表／编码与列映射 → 后端预检 → 查看样例和错误 → 确认导入 → 结果清单。**

- 模板包含字段说明、必填项、格式和示例，模板说明页与数据页分开；CSV/TSV 模板说明通过页面提供。非标准表头允许人工映射到白名单字段，重复列、缺少必填列必须处理，不自动猜重要字段。
- 一次选择一个明确数据工作表；多张工作表不得隐式合并。列映射确认后冻结源文件哈希、模板版本、映射和校验批次，修改任何一项都需重新预检。
- 检查类型、金额精度、日期、引用编码、数据范围、重复记录、文件内总分金额及数据库冲突。错误清单包括工作表、原始行号、字段、原因和修正提示，支持 XLSX/CSV 下载并同样鉴权、脱敏和防公式注入。
- 一期默认全批预检无错误才可确认；执行阶段以“一个完整业务对象”为事务边界，例如一张草稿和其全部费用明细，绝不逐明细生成半张单。基础数据以单个记录为边界。
- 正式执行重新检查权限、引用状态和唯一约束，因为预检之后数据可能变化。允许出现部分成功，结果精确到业务对象；失败对象可修正重试，成功对象不重复写入。页面必须说明不是整个文件跨事务回滚。
- 导入模式一期默认仅新增；按指定业务键更新基础档案为 P1，需预览差异和版本校验。禁止依据姓名、Excel 行位置或空主键推断覆盖目标。
- 源文件摘要用于提示重复上传，不能单独作为业务去重。模板必须有批次内稳定对象键，重试幂等范围包含用户、导入批次和对象键；修正批次保留成功对象引用。新批次业务重复按业务键校验或提示，不承诺能自动识别任意重复草稿。
- 取消在未开始执行的对象前生效，已提交对象保留；撤销导入仅可对仍为草稿且版本未变的对象逐项执行受控删除/作废。不得直接数据库回滚整批已被后续业务使用的数据。

### 10.7 解析安全和并发上限

表格导入使用独立 `/data-imports` 类型上传入口；原附件白名单仍为 jpg/png/pdf，不向普通发票附件开放 Excel。模板、原文件、错误报告全部在私有存储中按用户和业务范围授权。

初始限制：单文件 10MB、1 万数据行、100 列、单单元格文本最多 4,000 字符；XLSX 解压后的累计内容最多 100MB，另限制压缩比、条目数和解析时间。业务字段自身更短的限制优先。以上均为待压测配置，不承诺任意 10MB 文件都能导入。

拒绝密码保护、宏和嵌入执行对象；不执行公式，不使用公式缓存值作为财务金额。数据区域发现公式单元格要求先转换为确认后的值；禁止解析器访问外部链接，XML 禁用外部实体。导入预览只呈现转义文本，不呈现 HTML。

解析放在受限 worker，支持内存、CPU、临时磁盘及超时限制。XLSX 使用事件读取，XLS 使用 HSSF 事件模型，文本使用流式解析；错误记录分批落库，不在内存保存整份文件或全部错误。

导入和导出分别限流，初始每 worker 同时 1 个导入、1 个导出，每用户各最多 1 个活跃任务。每批按约 200 个业务对象领取调度，各对象独立短事务；大小按压测调整，不在一个超长事务内写完整文件。复用租约、重试及任务幂等机制，OCR 原配置不变。

### 10.8 填单、审批和打印细节

**草稿：**有效修改停止约 3 秒后自动保存，展示“保存中／已保存时间／保存失败”；失焦或离开页面时尝试保存，失败明确提醒。服务端使用版本条件更新，同一单据多标签编辑发生冲突时让用户比较和选择，禁止静默覆盖。敏感表单不默认写入 localStorage；刷新后恢复最近服务端草稿，离线不显示保存成功。

**费用明细：**增加费用类型、发生日期、说明和金额，按单据汇总；总额采用用户确认且后端核对，不改变 OCR 金额确认规则。附件可以关联费用行，不能因多个关联重复占用同一发票。删除最后一行、修改币种或精度等规则由后端统一校验。

**复制与模板：**复制单据仅带入行程、常用费用类型和备注等允许字段，金额和日期要求重新确认；不复制票据号、附件绑定、审批结果或付款信息。常用差旅模板 P1 存储，与权限和实际附件分离。

**审批：**列表进入详情后显示表单和附件分栏，支持缩放、旋转显示、翻页及上一笔／下一笔；显示待办数量、当前节点、提交时间和逾期标记。通过后加载下一笔前再次核验权限与状态；已有其他人处理则跳过并提示。常用意见只预填文本，不能代替人工核验。

**退回：**必须填写原因，可以标注相关字段和缺少的材料；重新提交展示相对上次提交的字段、明细和附件变化。需要版本快照，不能仅依据 updated_at 重建修改差异。退回和驳回含义与原状态机保持一致。

**批量操作：**P0 支持明确选中记录的导出；P1 可增加受限批量主管审批，先列出单据和风险提示再确认，单批最多 50 单，每单独立鉴权、版本校验、幂等事务和审计。部分失败返回逐单结果；禁止对动态“所有搜索结果”一键审批。财务最终通过一期仍逐单处理。

**打印：**专用 A4 打印页包含单号、申请人、部门、行程、明细、总额、审批轨迹、打印时间及页码适配；附件默认打印清单，不自动打印所有原件。草稿带草稿标识，已变更单据标明版本；浏览器打印可另存 PDF，分页和字体按目标浏览器验收。打印页鉴权，编号或二维码如后续增加，只能定位仍需登录的页面。

### 10.9 数据模型

费用行、导入导出、引导表已并入第 5 节，此处不另建一套。`user_view_pref` 仍为 P1，不进一期库。导入源文件与错误报告 7 天清理；未确认预检 24 小时过期。

### 10.10 增补验收清单

| 场景 | 验收结果 |
| --- | --- |
| 中文输入法确认候选词、长按保存键 | 不误提交、不重复生成业务记录 |
| 无鼠标填写、查看附件和关闭弹窗 | 焦点顺序合理，无键盘陷阱，动作有可见反馈 |
| 自动保存失败或双标签同时编辑 | 不误显示已保存，冲突可见且人工处理 |
| XLSX/XLS/CSV/TSV 使用同一份规范样例导入 | 形成相同业务值；票号、工号前导零及长编号保持正确，可检测的科学计数法或精度异常被拦截；源文件已丢失的数字不能自动恢复，要求提供文本格式原值 |
| CSV 引号、换行、中文编码；Excel 日期与空值 | 无错列、乱码或静默日期转换；歧义要求确认 |
